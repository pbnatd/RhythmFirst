# ADR 0002: BPM остаётся проверяемой подсказкой, а партия продлевается целиком

Статус: принято

## Контекст

Для структуры песни, переходов и синхронного сопровождения нужна единая временная сетка. При этом запись с обычного микрофона может содержать шум, синкопы и восьмые доли, из-за которых автоматический анализ путает основной темп с половинным или двойным. Также исходный грув часто короче желаемого музыкального эскиза; дополнение тишиной разрушает пользовательский сценарий.

## Решение

- сервер оценивает BPM по автокорреляции огибающей атак в диапазоне 70–160;
- интерфейс показывает BPM и уверенность как редактируемую подсказку;
- ручное значение пользователя является окончательным для рендера;
- длина исходной записи отделена от длины результата;
- если запись короче результата, подготовленная партия повторяется целиком и обрезается точно по целевой длительности;
- исходная и продлённая барабанные дорожки сохраняются отдельно;
- генерация новых ударов, филлов и переходов не входит в этот этап.

## Последствия

Пользователь может быстро получить длинный эскиз из короткого грува, а ошибки автоматического темпа не блокируют работу. Граница повторения пока зависит от того, насколько ровно записана исходная фраза. До появления детектора тактов и секций приложение не заявляет, что музыкально достраивает барабанную партию.

Следующий этап должен ввести явную модель секций песни и только после этого разрешить LLM предлагать места изменений. Выход LLM должен быть структурированным и проверяться сервером до синтеза.
