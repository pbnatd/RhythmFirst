# ADR 0001: Первый MVP использует ручной темп и локальный синтез

Статус: принято

## Контекст

Rhythm First разрабатывает один человек за четыре месяца. У пользователя нет электронных барабанов, поэтому входом должна быть запись обычного микрофона. Главный ранний риск — не точность ML-модели, а ценность самого результата: воспринимается ли автоматически добавленное сопровождение как музыка, построенная вокруг собственной партии барабанщика.

## Решение

Первый вертикальный срез:

- принимает запись с микрофона или аудиофайл;
- просит пользователя вручную указать BPM;
- ограничивает форму размером 4/4 и 8/16 тактами;
- создаёт бас и клавиши детерминированным локальным синтезатором;
- использует три заранее заданных стилевых пресета;
- сохраняет исходную дорожку барабанов и сводит её через FFmpeg;
- не использует LLM и внешние музыкальные API.

Гармония считается интерпретацией выбранного стиля, а не распознанным свойством барабанной записи.

## Последствия

Положительные:

- сквозной прототип можно проверить до разработки сложного анализа аудио;
- нет затрат на API и зависимости от GPU;
- результат воспроизводим и объясним;
- ошибки темпа отделены от качества аранжировки.

Ограничения:

- пользователь должен знать или подобрать BPM;
- сопровождение пока реагирует на сетку, но не на конкретные акценты и динамику записи;
- синтезированные тембры предназначены для продуктового теста, а не финального музыкального качества.

## Условие пересмотра

После подтверждения ценности на реальных записях добавить анализ BPM, onsets и динамики. LLM подключать только для ограниченного плана аранжировки с валидируемым структурированным выходом.
